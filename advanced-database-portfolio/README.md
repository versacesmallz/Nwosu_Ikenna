# MIT 8103 Advanced Database Systems — Practical Portfolio

**Student:** Ikenna Nwosu · **Student ID:** 202609417 · Master of Information Technology, Miva Open University · 2026/2027 First Semester

**Case study:** *Kasuwa Marketplace* — a simulated Nigerian multi-vendor e-commerce platform. Sellers list products, customers in all 36 states and the FCT order online, payments are taken by card / transfer / USSD / wallet / pay-on-delivery, and couriers deliver. Database users: customers, sellers, operations, finance, management and the platform application. Major data: customers, addresses, sellers, product catalogue and categories, inventory, orders and order lines, payments, deliveries, reviews. Key operations: place order, update stock, search catalogue, track delivery, review products, report sales by region. Full statement: [Portfolio 1 README](portfolio-1-database-design/README.md#1-case-study-kasuwa-marketplace-simulated-organisation).

The same case study and the same data set (300,000 orders, 600,153 order lines, 50,000 customers, 5,000 products) are used in all five activities.

## Portfolio map

| # | Activity | Main evidence | Headline result |
|---|---|---|---|
| 1 | [Database design and modelling](portfolio-1-database-design/) | ERD, DDL with 14 tables, normalisation to BCNF, 10 constraint tests | every invalid operation rejected by the DBMS |
| 2 | [Query processing and optimisation](portfolio-2-query-optimisation/) | 5 workload queries, 15 saved execution plans, benchmark harness, chart | 3.7× to ~42,000× faster; a failed first attempt diagnosed and fixed |
| 3 | [Transactions and concurrency](portfolio-3-transactions-concurrency/) | COMMIT/ROLLBACK/SAVEPOINT transcript, 7 concurrency scenarios with real sessions | naive flash sale oversold 40 units; atomic UPDATE oversold 0 |
| 4 | [NoSQL and advanced data models](portfolio-4-nosql/) | Redis key-value, JSONB document store, MongoDB-API version | flash sale correct in Redis; same answers from JSONB and MongoDB API |
| 5 | [Distributed and cloud databases](portfolio-5-distributed-cloud/) | 4-node replication + sharding lab, 8 experiments, cloud design | aggregate pushdown 4× faster; failover with no committed data lost |

## Run everything from scratch

```bash
createdb kasuwa
psql -d kasuwa -f portfolio-1-database-design/01_schema.sql
psql -d kasuwa -f portfolio-1-database-design/02_seed_data.sql
psql -d kasuwa -f portfolio-1-database-design/03_constraint_tests.sql
python3 portfolio-2-query-optimisation/run_benchmark.py
psql -d kasuwa -e -f portfolio-3-transactions-concurrency/01_commit_rollback_savepoint.sql
python3 portfolio-3-transactions-concurrency/concurrency_demo.py
python3 portfolio-4-nosql/redis_keyvalue.py
psql -d kasuwa -f portfolio-4-nosql/document_model.sql && psql -d kasuwa -f portfolio-4-nosql/document_queries.sql
python3 portfolio-4-nosql/mongo_catalogue.py
sudo bash portfolio-5-distributed-cloud/01_setup_cluster.sh
psql -d kasuwa -f portfolio-5-distributed-cloud/02_sharding.sql
sudo python3 portfolio-5-distributed-cloud/03_distributed_tests.py
```

Each folder has its own README explaining what was implemented, how it was tested, and what the results mean. Raw outputs are in each folder's `evidence/` directory.
